# DSP provenance

Fugue is public and MIT-licensed. Every module, table and sample it ships
has to be ours to ship under that license. This document is for anyone
writing DSP for Fugue, and for reviewers of that work. It covers what may be
ported, what must be written clean-room, where data comes from, how ported
code is attributed, and how names are chosen.

Settle provenance before writing code, not after. Name the sources you mean
to use in the issue or PR first, and check them against this page.

## The rules

1. **MIT sources may be ported.** Translate them to idiomatic Fugue Rust:
   `f32`, block processing, a `ControlTable`, no allocation or locks on the
   audio thread. Adapt the code to Fugue's idioms rather than
   transliterating it line by line. A translation is still a derivative
   work, so every ported file carries an
   [attribution header](#attribution-header) and the source gets an entry in
   [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) with its original
   license text.
2. **GPL, unlicensed and unknown-provenance sources are reference only.**
   Write the module clean-room: work from manuals, papers, published
   descriptions and listening. Don't copy code, tables or constants, and
   don't keep the source open beside the editor while writing. The PR lists
   what was consulted.
3. **Data is ours.** Lookup tables, wavetables, samples and patches are
   generated by our own code or authored for Fugue. Mathematically derived
   tables (sine, exponential, pitch ratios, window functions) are fine to
   regenerate from their formulas. Never copy a table's values out of
   another project, even an MIT one; generate it.
4. **No trademarked names.** Modules, presets, examples, docs and UI are
   named by purpose (`resonator`, `granular`, `macro_oscillator`), never by
   another maker's product names. Naming the reference in a PR, an issue or
   a provenance note is fine; naming the Fugue module after it is not.
5. **Every PR states its provenance** with the line in the
   [PR template](../.github/PULL_REQUEST_TEMPLATE.md):

   ```text
   Provenance: original / ported from <source> (MIT, noted) / clean-room (consulted: …)
   ```

   Keep the one that applies and fill it in. A PR with no DSP says
   `original`.

Textbook forms (a one-pole damper, an allpass, a delay line, a biquad from
the RBJ cookbook, a Hadamard or Householder mix) are common knowledge, not
anyone's expression. Writing them from the textbook is generally original
work. The line is crossed when an implementation follows one particular
source's structure, names and tuning constants closely; then that source's
license applies.

## Attribution header

A ported file starts with a module doc comment that says what it was ported
from, under which license, and where the notice lives:

```rust
//! Ported from Mutable Instruments' `plaits/dsp/oscillator/variable_saw_oscillator.h`
//! (MIT, Copyright 2016 Emilie Gillet), adapted to Fugue's block processing.
//! See THIRD_PARTY_NOTICES.md.
```

Add the source to `THIRD_PARTY_NOTICES.md` the first time anything from it
is ported: the project, the revision ported from, the files used, the
copyright line, and the full license text. Later ports from the same
source add their files to that entry.

## Mutable Instruments' eurorack firmware

Much of the first-party DSP work draws on Mutable Instruments' open-source
eurorack firmware ([github.com/pichenettes/eurorack](https://github.com/pichenettes/eurorack);
the project works from the fork at
[github.com/gdamron/eurorack](https://github.com/gdamron/eurorack)).

The firmware's licensing is mixed: the README puts the STM32 projects
under MIT, the AVR projects under GPL-3.0 and the hardware under
CC-BY-SA-3.0. A file-by-file audit (2026-11-02) found:

| Source | License | How we may use it |
| --- | --- | --- |
| STM32 module DSP: Plaits, Rings, Clouds, Marbles, Tides 2, Stages, Warps, Elements, Braids, Peaks, Streams, Frames, Yarns, and the `stmlib` submodule | MIT | May be ported, with the attribution header and a notices entry |
| AVR modules: Grids, Edges, Branches, and `avrlib` | GPL-3.0 | Reference only: clean-room |
| Every module's `test/` directory, `braids/resources/waveshapers.py`, `elements/resources/samples.py`, `tools/` | GPL-3.0 | Don't port. Write our own tests and table generators |

Some material inside MIT-licensed directories has rights the MIT notice
can't grant. Exclude it:

- `plaits/dsp/speech/lpc_speech_synth_words.cc`: LPC-encoded words extracted
  from Texas Instruments ROMs.
- `plaits/dsp/speech/sam_speech_synth.*`: phoneme tables modelled on
  Software Automatic Mouth, a 1982 commercial program.
- `plaits/resources/syx/*.syx`: Yamaha DX7 factory banks and third-party
  banks. Never ship the `fm_patches` tables generated from them either.
- `plaits/resources/waves.bin` (the Braids wavetables): origin undocumented.
  Generate our own.
- `elements/samples/*.wav` exciter recordings: origin undocumented. Synthesize
  exciters instead.

The generated lookup tables in the MIT directories (`resources.cc` files)
are data. Under rule 3, regenerate each from its formula with our own code
rather than copying the values. The GPL generators
(`braids/resources/waveshapers.py`, `elements/resources/samples.py`) are not
ported.

"Mutable Instruments" is a registered trademark, and the firmware's README
asks derivative works not to reuse the module names. Rule 4 applies to
every one of them.

## Recorded audits

- **Reverb (2026-11-02).** The original `reverb` core was found to be a close
  translation of the GPL-2.0+ `gverb.c`: the same per-sample steps, names,
  Hadamard function and tuning constants. It was replaced (2026-11-03) by an
  original design, a multichannel diffuser feeding a feedback delay network,
  written from published descriptions (see
  [`src/modules/reverb/network.rs`](../src/modules/reverb/network.rs)). No
  GPL code remains and the reverb needs no notices entry. The `dsp/` damper,
  allpass and delay-line helpers are textbook forms and were fine as they
  were.

Add an entry here when an audit finds something, with what was found and
what was done about it.

## Crate dependencies

Rust dependencies are checked in CI by `cargo deny check licenses`, against
the allow-list in [`deny.toml`](../deny.toml). The list holds the permissive
licenses the current dependency tree uses. A new dependency whose license
isn't on it fails CI. Don't widen the list to get past that: copyleft
licenses (GPL, LGPL, AGPL, MPL) stay off it, and a new permissive license
is added only after reading it. Run the check locally with:

```sh
cargo install cargo-deny --locked
cargo deny check licenses
```
